## Decisions and assumptions

- **Math syntax: raw `$...$`/`$$...$$`, not the `<Math>` component.** Both
  exist in the codebase (a registered `Math` component with its own unit
  tests, and global `remark-math`+`rehype-katex` config in `next.config.ts`),
  and `docs/contracts/content.md` doesn't disambiguate — it only says
  "Inline/display math uses KaTeX-compatible LaTeX." I checked for
  precedent instead of guessing: `content/fixtures/mdx-renderer.mdx` (the
  P2.2 fixture built specifically to prove out supported syntax) uses raw
  `$`/`$$` exclusively, including for mhchem chemistry notation, and the
  `<Math>` component has **zero** usages in any real content file. I
  followed the demonstrated, already-validated convention. This is not the
  "Math component syntax unclear, wait for Owner" case your instructions
  flagged — there's clear existing precedent, not an open question.
- **Owner's LaTeX for the T08 pair uses `\text{}`, not mhchem `\ce{}`.**
  `docs/contracts/content.md` says reactions "use mhchem syntax when
  semantic conversion is reliable," and genuine mhchem would be `\ce{aA +
  bB <=> cC + dD}`. I inserted the Owner's approved string **exactly as
  given** — I did not "fix" it to mhchem myself, since silently changing
  approved chemistry-adjacent notation is exactly the kind of unauthorized
  judgment call I was told not to make. Flagging it here in case the Owner
  wants to revisit in a later pass; not acted on.
- **`sourceId="T08-S01:e6352"` vs `sourceId="T08-S01"`:** your instruction
  used the former; all 31 existing `ChemFigure` usages in this exact file
  use the latter (source-document id only, no issue suffix). I would have
  followed the established convention here too, per "dùng đúng convention
  đã có trong P4.1; không tự đặt path mới nếu không rõ convention" — moot in
  the end since I didn't apply the ChemFigure at all (see below), but
  flagging the discrepancy for when someone does.
- **ID traceability via a single-line `{/* issueId */}` comment.**
  `scripts/validate-content/validate.py` rejects a blocking-severity id that
  disappears entirely from the MDX body ("hidden unresolved blocking
  issue"). Removing a Callout that quoted the id and replacing it with pure
  LaTeX would trip that rule. I tested three things empirically before
  committing to this: (1) HTML comments (`<!-- -->`) are not valid MDX
  syntax at all — the compiler rejects them outright; (2) a **multi-line**
  `{/* ... */}` JSX comment, immediately followed by plain paragraph text
  (not a heading), gets mangled by Prettier's markdown emphasis normalizer
  into `{/_ ... _/}` — this is the exact bug that broke a prior task's
  build, and I reproduced it precisely to confirm the trigger condition;
  (3) a **short, single-line** `{/* T06-S01:e6259 */}` survives Prettier
  and `npm run format` untouched in every position I tested, including the
  exact risky one (followed by plain paragraph text). I used single-line
  comments throughout for this reason, verified by compiling both edited
  files through the real MDX pipeline and by the full `npm run verify`.
- **Blocked item: `T08-S01:e6352` was not applied.** Before wiring the
  approved image into `ChemFigure`, I re-extracted and re-inspected
  `public/qa-preview/lessons/chuyen-de-08/e6352.png` at the exact target
  commit (not trusting my own memory from the earlier triage report) —
  `identify -verbose` (152×108px, 261 colors, not blank) and a 400% zoom.
  The image is **garbled Vietnamese text only** ("chi c à thua ä" / "chi c à
  ngh ò ch" — a corrupted rendering of "chiều thuận"/"chiều nghịch"), with
  **no arrows, no diagram, no visual symbols at all**. The approved alt text
  ("Sơ đồ mũi tên biểu thị chiều thuận và chiều nghịch...") and caption
  ("Chiều thuận (↑) và chiều nghịch (↓)...") both describe an **arrow
  diagram** that isn't in the file. Given `public/qa-preview/README.md`'s
  own explicit rule — these images "must never be wired into a lesson's MDX
  as a `ChemFigure` fallback" without deliberate review — and your
  instruction to report rather than guess when something doesn't check out,
  I left the `T08-S01:e6352` Callout exactly as it was. The Owner's decision
  is still fully recorded (`remediationChoice: "reviewed-image-fallback"`,
  the exact alt/caption text, `status: "blocked"`) so nothing is lost; it
  just isn't live in the lesson content. See "Remaining work" for the exact
  question that needs answering.
- **`content/qa/pending/<lesson>.json` (the real `LessonQaRecord`) is
  untouched** — confirmed by empty `git diff --stat` against those two
  exact paths before doing anything else. Per `docs/contracts/content.md`
