# Task P4.1 — Copilot: importer, validator and staging assets

## Assignment

Complete the hybrid importer for Topics 6 and 8, produce deterministic `draft` MDX,
content-addressed staging assets and machine-readable failure/QA reports. Build a
validator for frontmatter, manifest provenance, links/assets and unresolved blocking
issues. Never publish content and never infer chemical correctness.

## Ownership

- Branch: `phase/p4-1-importer-validator` from current `main`.
- Allowed: `scripts/import-docx/**`, `scripts/validate-content/**`, bounded validator
  tests/fixtures, generated Topic 6/8 `draft` files, staging asset manifest,
  `docs/pilot-metrics.md`, `docs/handoffs/P4/P4.1-copilot.md`.
- Forbidden: auth/DB/R2 runtime adapters, `src/app/**`, shared MDX component styling,
  production workflows, ADR/contracts, lesson status `published`.
- `package.json`/lockfile may change only if strictly required; P4.2/P4.3 must not edit
  them concurrently.

## Definition of done

- Safe rerun refuses to overwrite manual edits without explicit backup/diff flow.
- Source IDs/paths match `docs/source-manifest.csv`; only Part I is included.
- Strategy B is enforced: semantic text/headings/tables where verified; complex
  formula/OLE/figure becomes visible reviewed fallback, never silent omission.
- Asset names use content hashes; every MDX reference resolves in staging.
- Validator rejects invalid/missing metadata, duplicate slug/order, broken asset/link,
  report drift, `published`, and unresolved hidden blocking failures.
- Add black-box coverage for DOCX and Topic 8, then run documented verification.
- Write the required handoff and commit/push the task branch; do not merge `main`.
