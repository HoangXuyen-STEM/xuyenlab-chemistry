## Decisions and assumptions

- v1 ships one (light) theme only; tokens are named semantically so a future
  dark theme would not require renaming call sites. Not an ADR-level decision,
  just a documentation convention — flagged in the file itself.
- Styling implementation layer (CSS custom properties vs. Tailwind theme,
  etc.) is intentionally left open, matching P1.1's decision not to couple app
  bootstrap to a premature styling choice (`docs/handoffs/P1/P1.1-codex.md`).
- Route list (`/`, `/dang-nhap`, `/dang-ky`, `/quen-mat-khau`,
  `/dat-lai-mat-khau`, `/thu-vien`, `/chuyen-de/[topic]`,
  `/chuyen-de/[topic]/[lesson]`, `/tim-kiem`, `/tien-do`, `/giao-vien`,
  `/giao-vien/hoc-sinh/[id]`, `/khong-co-quyen`) is derived from KE_HOACH §1.3
  scope and the `docs/contracts/backend.md` operations list; it is a UX
  proposal, not a frozen contract — Phase 3 owns the actual Next.js route
  structure.
- Four items could not be resolved without inventing new backend behavior;
  recorded as open questions in `docs/ux-spec.md` §8 instead of decided here:
  the exact "not on allowlist" signal, the `saveReadingPosition` debounce
  value, `/tim-kiem` matching semantics, and `getTeacherOverview`
  pagination/sort defaults.
- No ADR or existing contract was changed. This task added documentation only
  and did not touch `src/`, `content/`, `db/`, `scripts/`, `.github/`, or any
  shared implementation file.
