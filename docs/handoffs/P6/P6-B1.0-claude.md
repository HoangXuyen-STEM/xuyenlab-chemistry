## Follow-up: pre-merge integration review response (same day, same PR)

Review before merge found two real gaps in the original submission, both fixed
in the same PR, plus one lower-severity addition:

- **Importer safeguard (blocker).** The original submission noted, as a
  contract *rule*, that importers must not clobber another lesson's
  already-recorded status/QA content — but never verified `pilot_import.py`
  actually honored it. On inspection, it doesn't: its existing manual-edit
  drift check compares each managed file's *recorded* hash (from the last
  committed manifest) against its *actual on-disk* hash. For an already-signed
  `in_review` lesson, those are identical by definition (nothing manually
  edited it), so no drift is ever detected — meaning a plain rerun of
  `pilot_import.py` against the real repository today would silently
  regenerate both signed pilots as fresh unsigned drafts, erasing their
  `reviewer`/`checks`/`approvedForPublish`/`publishWaiver` state, without even
  needing `--force`. Added `refuse_if_any_lesson_in_review()`, called at the
  very top of `main()` before any generation work: if the manifest has *any*
  `in_review` lesson, the importer refuses immediately, before writing
  anything, and this is not bypassable with `--force`/`--backup-dir`. New
  regression test `"P6-B1.0 safeguard: importer refuses to run against an
  in_review baseline, writing nothing"` promotes both pilots to a QA-signed
  `in_review` state matching the real committed manifest, hashes every managed
  file, attempts a rerun (with and without `--force`), and asserts both the
  refusal and that every hash is unchanged afterward.
- **PDF generator status filtering (blocker).** `scripts/generate-pdf/generate.ts`
  built a PDF plan for *every* manifest lesson unconditionally — the original
  handoff flagged this as an observation but left it unfixed. Once a `draft`
  Topic 24 lesson exists, this would have attempted to plan/render it too.
  Extracted the lesson-selection logic into an exported pure function,
  `selectPdfEligibleLessons()`, that filters to `status === "in_review"`
  before any plan is built; a `draft` lesson is skipped, not errored on. Also
  added the `import.meta.url === file://process.argv[1]` execution guard
  (matching the existing pattern already used in `scripts/generate-pdf/upload.ts`)
  so the module is safely importable for testing without triggering a live
  Playwright/Next.js run as a side effect of import. New test file
  `tests/pdf/generate.test.ts` (`tests/pdf/` already holds
  `pipeline.test.ts`/`upload.test.ts` for this script directory, since
  `scripts/**` isn't in vitest's `include` globs) covers: a mixed
  draft+in_review manifest plans only the in_review lesson; an all-draft
  manifest plans nothing without throwing; an all-in_review manifest
  (matching current production) plans everything.
- **`manifestVersion` check (minor, requested but non-blocking).** Added
  `MANIFEST_VERSION = "1.1.0"` to `validate.py` and a check that the manifest's
  `manifestVersion` matches it exactly; a stale (e.g. pre-P6-B1.0 `"1.0.0"`) or
  missing value now fails validation with a specific message instead of being
  silently accepted. New negative-case assertion added to the existing
  mixed-status contract test.

All three are additive to the original design — no earlier rule, test, or
migrated pilot state was changed to make these pass.

## Decisions and assumptions

- Kept the manifest's filename (`pilot-staging-manifest.json`) and top-level
  `scope`/`strategy` fields unchanged. The name is historical; renaming it was
  out of scope for a schema-only contract task and would have widened the diff
  across every consumer for no functional benefit. Documented this explicitly
  in the new contract section so it doesn't read as an oversight.
  - `strategy: "hybrid"` remains a genuine batch-wide (not per-lesson) value —
    it describes the conversion approach for the whole pipeline, not an
    individual lesson's lifecycle, so it correctly stayed a top-level field.
- Chose to reject a lingering top-level `publicationStatus` key outright
  (rather than silently ignore it) so an unmigrated manifest fails loudly with
  an actionable message instead of silently validating with stale/ambiguous
  semantics.
- Chose `loadPilotLibrary()`'s new default-parameter shape (`manifest = ... as
  {...}`) over `vi.mock`-based JSON import mocking for testability — smaller,
  more robust, and keeps the production call site (`loadPilotLibrary()`, no
  args) completely unchanged.
- Did not touch `pilot_import.py`'s hardcoded `PILOTS` tuple, CLI arguments, or
  drift/backup logic — only the manifest *shape* it writes. Full
  parameterization for arbitrary topics is explicitly P6-B1.1's deliverable per
  `COORDINATION.md`.
- Did not import Topic 24, touch chemistry content, change any
  `approvedForPublish`/`publishWaiver` value, or perform any R2/production/auth
  work — all explicitly excluded for P6-B1.0.
