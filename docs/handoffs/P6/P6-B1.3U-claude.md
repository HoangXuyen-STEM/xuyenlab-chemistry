## Decisions and assumptions

- **Presentational components take pre-loaded data as props, not fs
  access.** `PilotLessonShell`, `AcceptedLimitations` and
  `DiscussionPrompts` are pure/presentational; each page's server component
  calls `loadRemediationQueueSummary(manifest)` and passes the result down.
  This keeps the components trivially unit-testable with synthetic data
  (no fs mocking) and mirrors how `manifest` itself is already loaded and
  passed down.
- **Queue paths are never caller-supplied.** `loadRemediationQueueSummary`
  takes `{ topic, slug }` (always sourced from an already-validated
  `PilotLessonManifestEntry`), re-validates the shape with the same
  `chuyen-de-\d{2}` / kebab-case patterns used elsewhere, and derives the
  queue path itself — there is no path parameter a caller could substitute.
  `library.ts`'s `loadPilotLibrary` reuses the pure
  `parseRemediationQueueSummary` (not a second fs-reading path) over its
  own already-`allowedPaths`-gated reader, so the P5 library's
  containment/symlink guarantees (P6-B1.3 round 1) extend to this new read
  unchanged. Added the derived remediation-queue path to `allowedPaths` in
  `validateManifestLessons` — additive; nothing removed from the allowlist.
- **Fails safely everywhere.** A missing file, a JSON parse error, a
  non-array top level, or an individual item missing a required field never
  throws past the read model — it is treated as "no data to show," not a
  page error. Verified directly: `loadRemediationQueueSummary` with a
  throwing reader, and `parseRemediationQueueSummary` on malformed JSON /
  non-array input / a shape-incomplete item, all return the empty summary
  (see `src/features/content/remediation-queue.test.ts`).
- **No chemistry inference.** Every rendered string is either a literal
  required by the task (the notice, `scientificStatus`/`identityAssurance`
  meanings) or copied verbatim from a declared field (`issueId`, `sourceId`,
  `qaNote`, `promptOrObjective`, `recordedBy`, `decidedBy`, dates). Nothing
  is derived, summarized, or reworded from chemistry content.
- **No `noindex`/staging-only/login behavior changed.** No route,
  `robots` meta, or auth check was touched; the new sections are additive
  content inside already-existing staging routes.
- Placed `AcceptedLimitations`/`DiscussionPrompts` after the lesson body
  inside `<article>` (trailing sections, same prose column, so print
  pagination and the existing heading-level checks keep working
  unmodified) rather than in the sidebar grid column.
- Real committed data currently has zero `accepted-with-limitation`/
  `discussionPrompt` items (P6-B1.3P was schema/validator-only), so in
  production today both new sections render nothing and
  `acceptedLimitationsCount` is `0` everywhere — this PR proves the
  presentation path with synthetic data (component props, injected
  readers, and a synthetic `PilotLibraryLesson`/manifest lesson), never by
  editing a real queue file.
