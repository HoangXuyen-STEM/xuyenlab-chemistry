## Decisions and assumptions

- Treated "preserve... blocked T08-S01:e6352" as the owner's example of the kind of
  reviewed exception this approval covers, not as a claim that every blocking item
  had been reviewed — confirmed this reading explicitly with the owner before
  proceeding, given the real numbers (95 and 165 unreviewed items respectively) are
  far larger than one named item.
- Scoped the validator exception as narrowly as the contract amendment allows: by
  exact `lessonSlug` allowlist, not a blanket phase-wide relax, not a manifest- or
  directory-based check, and not a change to any other validation rule (published
  status, hidden-blocker visibility, QA/report drift, etc.). Chose `lessonSlug`
  (a field already present in every QA record) as the key rather than, e.g., a new
  sidecar flag file, to keep the change minimal and auditable in one place.
- Did not attempt to mark any blocking item as "resolved" or edit any `unresolved`
  entry, remediation-queue doc, or MDX fallback content — that would have
  misrepresented the actual review state instead of accurately recording it.
- Did not change lesson `status` (still `in_review`) or
  `pilot-staging-manifest.json`'s `publicationStatus` (still `in_review`); the
  validator's separate, unmodified rule (`status == "published"` is always
  rejected) continues to block real publication regardless of this change.
