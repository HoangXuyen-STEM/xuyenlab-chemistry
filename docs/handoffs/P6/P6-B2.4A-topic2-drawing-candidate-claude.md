## Decisions and assumptions

- **Diagram meaning, fixed by the Owner, not invented:** two-way relation
  between atomic structure and periodic-table position, both feeding into
  element properties. Box labels: "Cấu tạo nguyên tử", "Vị trí nguyên tố
  trong bảng tuần hoàn", "Tính chất của nguyên tố" — taken directly from
  the Owner-specified alt text so the visual and its description stay in
  lockstep. No text on arrow shafts (a bidirectional arrow between the
  first two boxes; two converging arrows into the third). This mirrors —
  intentionally, since the Owner described it as "same teaching meaning"
  — the existing accepted `i6022` flowchart's own three-part structure,
  and the DataTable's own three-column layout directly above it in the
  MDX.
- **SVG chosen over PNG** (task's stated preference): vector, print-safe
  (pure black-on-white, high contrast, no dependency on rasterization
  settings), small (2,007 bytes), and rendered by the existing
  `ChemFigure` component with zero code change, since it emits a plain
  `<img src>`.
- **Content-addressed naming**, same convention as the existing T02 PNG:
  `public/staging-assets/lessons/<sha256[:2]>/<sha256>.svg`. Verified with
  a real `sha256sum` of the file, not assumed.
- **Not registered in `pilot-staging-manifest.json`'s top-level `assets`
  array.** `content:validate`'s asset-reference check (`HASHED_ASSET`
  match + on-disk hash verification) does not require manifest
  registration — it independently validates any correctly-named,
  correctly-hashed file referenced from MDX. Registration is what the
  automated importer does for its own pipeline-generated assets; this is
  a manually-added, not-yet-Owner-approved candidate, so registering it in
  the corpus-wide asset inventory as if it were a real, kept asset would
  overstate its current status. If the Owner approves it in this PR
  review, P6-B2.4B is the natural place to register it alongside
  resolving the remediation-queue item.
- **The MDX `body.mdx` fixture copy was regenerated** (`tail -n +17`),
  since the pre-existing `pilot-content-regression.test.ts` byte-identity
  check would otherwise fail — this is exactly the "sync fixture body
  only if required by existing conventions/tests" case the task
  anticipated, and it was required.
- **`content/pilot-staging-manifest.json`'s `mdxSha256` was refreshed**
  for the `bang-tuan-hoan` entry — a mechanical, required consequence of
  editing the canonical MDX (the same hash-drift check every prior P6
  content task has had to satisfy), not a status/lifecycle change.
  `qaSha256`, `blockingCount`, `warningCount`, `failureReportSha256` and
  every other lesson's entry are untouched.
- **No test needed updating.** The full unit suite (300 tests) and focused
  Playwright suite (25 tests) both passed unchanged — no existing
  assertion counts "exactly N images" or otherwise assumed only one
  `ChemFigure` on this page, so adding a second one broke nothing. No
  assertion that the Callout/`T02-S01:d1402` blocking status still exists
  was touched or weakened.
