## Method

1. Copied the source `.docx` to an isolated scratch directory (never moved
   or modified the repo original) and unzipped it there.
2. Parsed `word/_rels/document.xml.rels` to map every relationship ID to its
   package part (image or OLE embedding).
3. Located the Part I / Part II boundary by exact heading-text match
   (`"Phần I: HỆ THỐNG..."` / `"Phần II: HỆ THỐNG..."`, each occurring
   exactly once).
4. Traced every `r:id`/`r:embed` reference inside the Part I body region back
   through the relationship map, classifying each referenced object as
   Part I / Part II+ / orphan / header-footer. Cross-checked three
   independent ways (targeted tag regex, broadest possible `r:id`/`r:embed`
   regex, exhaustive `docPr` enumeration) — all three converged.
5. An isolated dry-run of the actual converter (`scripts/import-docx/
   prototype.py`) was attempted against a temp output directory. It first
   failed against a **stale local git worktree** whose disposition allowlist
   had not yet been broadened to include `import_part_i` — this was
   initially and incorrectly reported as the real gate. Re-run against the
   true `origin/main` (`5d229b9`) succeeded (exit 0) and produced the real
   classification directly, superseding the earlier code-path inference.

  vector AutoShape ("Arrow: Left-Right-Up 16", pure `prstGeom`, no
  relationship reference).
- Real converter dry-run output for Part I: 42 blocks total, 39 semantic, 3
  fallback:
  - `EXTRACTED_IMAGE_REQUIRES_REVIEW` (warning) — the PNG image.
  - `DOCX_TABLE_REQUIRES_VISUAL_REVIEW` (warning) — a flattened
    "Cấu tạo nguyên tử / Vị trí của nguyên tố" summary table (all cells
    literally `?` placeholders). This table was **missed by the manual
    relationship-tracing sweep**, which only checked for `a:blip`/
    `v:imagedata`/`o:OLEObject`/bare-`w:drawing` tags and never checked for
    `<w:tbl>`. The real converter run caught it; the manual method did not.
  - `UNSUPPORTED_NON_IMAGE_DRAWING` (blocking) — the arrow AutoShape.
- Part I boundary, by stable per-part block index (not raw XML character
  offset, which is not stable across re-serializations): begins at
  `word/document.xml#body/p[3]` (heading text "Phần I: HỆ THỐNG..."); the
  importer's own boundary logic stops after block 42, immediately before
  the Part II heading. Last three Part I blocks: image at `p[41]`
  (`block[41]/a:blip[@r:embed='rId7']`), table at `body/tbl[1]`, arrow at
  `body/block[43]/w:drawing[1]`.
