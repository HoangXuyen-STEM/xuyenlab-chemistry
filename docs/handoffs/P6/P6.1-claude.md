## Remaining work, known issues and risks

- **Open question for project owner:** an unexplained repository secret
  `R2_PUBLIC_BUCKET` exists alongside the four secrets named in the P6 brief. Not
  used by any workflow in this repo as of this handoff. Confirm whether it is
  intentional (e.g., planned for a future public-asset pipeline) or should be
  removed.
- **Accepted risk (owner-approved):** the approval gate for live R2 uploads is now a
  workflow-dispatch input plus repository write-access control rather than a GitHub
  environment required-reviewer rule. This is weaker in one respect — GitHub's
  environment reviewer feature blocks the *job* until a reviewer approves it
  in-flight, whereas `owner_approved` is a self-reported boolean anyone with write
  access could set to `true` without a second person's review. Mitigated by: the
  repository has a small trusted-write-access set, the job still requires the commit
  to be an ancestor of `main`, and the workflow remains fully idempotent/dry-run-safe
  by default.
- P6.1 does not include triggering a live upload. That remains for a follow-up,
  explicitly authorized step once this PR's CI and Vercel checks are green.
- P6.2 (flip `approvedForPublish`) and P6.3 (production deploy) are out of scope for
  this handoff and require separate project-owner authorization per the P6 brief's
  governance principles.
