## Decisions and assumptions (Phase 1 implementation)

- **Scope narrowly to `kind: "drawing"`**, matching the exact
  narrow-scoping discipline already used for `owner-accepted-source-fidelity`
  (table-only) and `owner-accepted-visible-fallback` (image-only) — "initial
  supported use," extending further requires a later amendment.
- **Required `ownerDecision` fields, mirroring the existing
  `owner-accepted-visible-fallback` pairing discipline but adapted for a
  resolved item**: `decidedBy`/`decidedAt`/`qaNote` required (as for every
  disposition); `altText` and `caption` **required non-empty** (opposite of
  `accepted-with-limitation`, since content actually _was_ authored here);
  `reviewedLatex` must stay `null` (this is an image/diagram replacement,
  not a LaTeX recreation — that remains `reviewed-latex-mdx`'s role).
- **Single-`ChemFigure` pairing check**, exactly mirroring
  `owner-accepted-visible-fallback`'s existing discipline: `previewPath`
  and `ownerDecision.altText`/`caption` must all match one `ChemFigure`'s
  `src`/`alt`/`caption` on the same element.
- **Callout removal required**: mirrors the pre-existing `applied`/
  `reviewed-latex-mdx` rule exactly (a resolved item doesn't keep its
  warning Callout).
- **`QA.unresolved` and `blockingCount`/`warningCount` are explicitly
  documented as unaffected** by this new pairing, matching the proven
  behavior of every existing disposition type in this project (Phase 0
  finding D) — this is stated in the contract prose itself, not left
  implicit.
- **Not a publication authority.** Explicitly stated in the new contract
  section, mirroring every other disposition type's own non-publication
  clause.
- **No Python test infrastructure exists in this repo** (`scripts/
validate-content/` has no test file at all; the validator is only
  exercised via `npm run content:validate` against real content and via
  the TS regression tests). Rather than introduce new test infrastructure
  as a side effect of a policy PR, the new validator function
  (`validate_applied_image_fallback`) was proven directly by importing the
  module and calling it with synthetic positive/negative cases — see
  Verification below for the real executed output. This does not touch or
  depend on any real committed content.
