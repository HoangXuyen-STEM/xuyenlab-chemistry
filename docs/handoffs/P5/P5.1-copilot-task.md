## Objective

Implement a deterministic, credential-free PDF dry-run keyed by the canonical lesson
content hash, and make CI validate content, links, assets and PDF generation without
cloud writes. Prepare a guarded post-merge development-R2 upload path; do not execute
an upload without explicit project-owner authorization.

## Required behavior

- Derive the private object key exactly as
  `pdf/<lesson-slug>/v<version>/<content-hash>.pdf`.
- Define `content-hash` as lowercase SHA-256 of the canonical MDX file bytes exactly
  as checked out, with no timestamp, generated PDF byte or environment input. Public
  assets are independently validated by their immutable content-addressed URLs and
  are not re-hashed into this value.
- Record lesson slug/version, canonical MDX path/hash, referenced asset keys/hashes,
  generator version and output path/key in a deterministic JSON manifest. Record
  duration and produced byte size separately as non-identity run metrics. Use the
  repository's locked Playwright Chromium to print the existing
  no-login pilot fixture from a local production Next build. Write derived files to
  `generated-pdf/<lesson-slug>/<content-hash>.pdf` and
  `generated-pdf/<lesson-slug>/<content-hash>.manifest.json`; that directory is
  already Git-ignored.
- Determinism is required for the key and manifest identity, not necessarily for PDF
  bytes containing engine metadata. A second run with the same content/generator
  reports `unchanged`; changing canonical MDX changes the key.
- If the content hash is unchanged but the recorded generator version changes, report
  `generator-changed` and stop. Regeneration then requires the explicit backup/
  replacement flow and a regression test; do not silently replace the same key.
- Validate lesson status and QA metadata without promoting status. P5 operates on
  owner-approved `in_review` staging content; production download authorization still
  requires `published` and is deferred to P7.
- Inherit `in_review`/QA validity from the accepted P4 lifecycle-aware validator and
  P4 summary. P5.1 must not invent a second QA-signature rule.
- PR CI must run without R2 credentials and must never upload.
- Local-link checking is required; external HTTP(S) link availability is explicitly
  UNVERIFIED in P5 unless a separate deterministic policy is approved.
- The initial upload workflow is `workflow_dispatch` against a commit reachable from
  protected `main`, uses the GitHub `development` environment and defaults to
  `dry_run: true`. A non-dry development upload requires explicit project-owner
  approval through a configured GitHub environment reviewer, asserts
  `R2_PRIVATE_BUCKET` is exactly `chem-private-dev`, checks object existence before
  upload and never overwrites by default. If that environment reviewer is not
  configured, mark the external upload rehearsal UNVERIFIED and do not upload.
  Production upload/execution is not authorized by this task.
- Use workflow concurrency per commit/content key and upload only the derived PDF plus
  its manifest. Store the manifest at the PDF key with `.pdf` replaced by
  `.manifest.json`, for example
  `pdf/<slug>/v<version>/<content-hash>.manifest.json`. Logs/artifacts must exclude
  credentials, signed URLs and provider responses containing sensitive headers.
- Regeneration of an existing key requires an explicit flag, a recorded backup or
  prior-object version identifier and rollback instructions; default behavior stops.
- Record measured PDF duration and artifact size before proposing new infrastructure.

## Definition of done

- Unit/integration tests prove key derivation, hash change behavior, idempotent rerun,
  missing/broken asset failure, existing-object no-overwrite behavior and absence of
  cloud writes in PR/dry-run mode.
- CI runs content/link/asset validation and PDF dry-run using repository fixtures.
- `npm run verify` and focused pipeline tests pass.
- No secret value is read into logs or committed.
- Write `docs/handoffs/P5/P5.1-copilot.md` using the handoff contract, including exact
  commands, timings, skipped external checks and rollback inputs.
