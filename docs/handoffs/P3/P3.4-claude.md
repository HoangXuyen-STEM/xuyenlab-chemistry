## Decisions and assumptions

- **Server actions over a client SDK** for sign-in. ADR-0003 requires server-side
  authorization and provider isolation; server actions keep the Neon SDK and the
  cookie secret server-only and still work without JavaScript.
- **Provider errors are never forwarded.** Failed sign-ins return one generic
  message so the form cannot enumerate accounts; only `EMAIL_NOT_VERIFIED` is
  distinguished. `requestPasswordReset` always reports the same neutral outcome.
- **Proxy fails open, the page guard fails closed.** Per ADR-0003 the proxy is
  navigation convenience; if it is unconfigured or throws, it passes through and
  `getReaderViewer()`/`requireUser()` still deny. `getReaderViewer()` returns `null`
  on any auth error, so an unconfigured environment looks anonymous rather than
  authenticated.
- **Degraded progress read.** `loadReaderProgress()` falls back to an empty progress
  state if the database is unreachable, so a missing migration cannot 500 the reader;
  save/complete/bookmark still surface real errors.
- Assumed post-login destination `/thu-vien` and Vietnamese UI copy consistent with
  `docs/ux-spec.md`. No new design tokens were added; auth error styling reuses the
  existing `--color-warning*` tokens.
- No sign-up screen was added: enrollment stays owner-controlled via
  `allowed_students` and `TEACHER_EMAILS` (ADR-0003).
