## Decisions and assumptions

- Auth roles are computed from server-only `TEACHER_EMAILS`, as frozen by the backend
  contract. `profiles.role` is retained as the required application-data record; P3
  does not sync it from Neon Auth automatically.
- Neon Auth SDK initialization is lazy. It avoids importing Next request APIs in unit
  tests and returns an `INTERNAL` application error when the two Neon Auth variables
  are absent.
- The database has no foreign key to Neon Auth tables. This respects the explicitly
  deferred foreign-key mapping in `docs/contracts/backend.md`.
- `markLessonComplete` persists an authenticated user’s own completion. P3.2/P3.3
  must invoke it only after their server route has established the staging fixture is
  an allowed lesson. A canonical content-status lookup does not exist yet, so the
  published-lesson assertion is **UNVERIFIED** rather than assumed.
