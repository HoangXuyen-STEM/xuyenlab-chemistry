## Decisions and assumptions

| Decision                                                                | Rationale                                                                                                                                                                             |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| String-based plugin names in `next.config.ts`                           | Next.js 16.3 Turbopack requires serializable (non-function) plugin references; function imports cause a build error.                                                                  |
| `import "katex/contrib/mhchem"` at config module level                  | The MDX/webpack compilation runs in the same Node.js process as `next.config.ts`; the module-cache side-effect registers `\ce` globally before `rehype-katex` calls KaTeX.            |
| `remark-math` + `rehype-katex` instead of `<Math>` component in MDX     | Keeps natural `$...$` / `$$...$$` syntax in content files. The `Math` component stays in the library for use in non-MDX JSX contexts.                                                 |
| HTML table elements inside `<DataTable>` instead of GFM markdown tables | GFM markdown tables compile to `<table>` elements which would nest inside DataTable's own `<table>`, producing invalid HTML.                                                          |
| Mock-based test for page import                                         | Adding `@mdx-js/rollup` to vitest to process real MDX would add an unused build dependency for tests; a `vi.mock` correctly fails if the import or render is removed from `page.tsx`. |
